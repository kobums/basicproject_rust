## Project Overview

Rust REST API starter template (basicproject_rust): axum 0.8, sqlx 0.9 (MySQL driver), tokio, MariaDB, edition 2024.
The Rust counterpart of basicproject_go. The template owns only auth/infra (login/signup/me, image upload, health,
DB pool, config, CORS). All table CRUD is generated by gomachine's Rust generator (`buildtool-model . rust`) from `db/schema.sql` +
`model.json`. HTTP contract, auth API contract and the unified JWT are the same as the Go/Spring templates (gomachine
README "인증 API 계약"). gomachine's `buildtool-model init` workspace mode copies this template for the Rust backend, so
keep `model.json` / `db/schema.sql` / `.env.example` aligned with gomachine `bootstrap/`. See README.md (Korean).

## Commands

```bash
cp .env.example .env   # first time; JWT_SECRET must be >= 32 bytes
make db-up             # MariaDB via docker compose (db/schema.sql runs on first start)
make gen               # buildtool-model . rust (needs the DB on port 3306 and ~/bin/buildtool templates)
make run               # cargo run (reads .env via dotenvy), default port 8008
make test              # cargo test (no DB needed)
make lint              # cargo fmt --check + cargo clippy --all-targets -- -D warnings
make check             # lint + test
make docker / make docker-up   # image / compose db + api (profile "api")
```

## Generated vs hand-written files

- Generated by gomachine (first line `// @generated by gomachine - do not edit`): `src/models/*.rs`,
  `src/handlers/*.rs`, `src/routes.rs`, `src/support/*.rs` except `auth.rs`. Never edit them; change
  `db/schema.sql` / `model.json` and run `make gen`, then commit the regenerated files. Regenerating is idempotent.
- User-owned, created by gomachine only if missing: `src/main.rs`, `src/support/auth.rs` (same as gomachine's default
  auth.rs: `JWT_EXPIRATION_MS`, `MIN_SECRET_LEN`=32 / `check_secret`). gomachine never updates an existing auth.rs, so
  port changes to its default by hand.
- Hand-written: `src/main.rs`, `src/config.rs`, `src/auth_api.rs`, `src/upload.rs`, `src/app_tests.rs`.
- gomachine runs rustfmt (with this crate's `rustfmt.toml`) on everything it writes when `rustfmt` is on PATH, so
  generated files pass `cargo fmt --check`; always run `make gen` with rustfmt installed. Keep
  `mod support; mod models; mod handlers; mod routes;` in main.rs (gomachine warns if missing).
- Do not put files with the generated header into `src/models` or `src/handlers` by hand: `make gen` deletes
  headered files for tables it did not generate.

## Architecture

- `main.rs` — loads `.env`, validates `JWT_SECRET` (`config::validate_jwt_secret`), builds the pool with
  `support::state::connect` (keeps the server time zone; never use `MySqlPoolOptions::connect` directly), serves
  `app(pool, &cors, upload_dir)`: `/api` + `/health` + `auth_api::routes()` + `upload::routes()` + generated
  `routes::routes()` (20MB body limit), plus `/uploads` (ServeDir of `{UPLOAD_PATH:-webdata}/uploads`). Port 8008.
- `config.rs` — pure env parsing (DATABASE_URL or DB_HOST/DB_PORT/DB_USER/DB_PASSWORD/DB_NAME, PORT, APP_MODE,
  CORS_ORIGINS defaults same as basicproject_go).
- `upload.rs` — `POST /api/upload/index` (login required, multipart field `upload`): extension whitelist + magic-byte
  check, 5MB image limit, random server-side filename, returns `{filename, url: "/uploads/{filename}"}`; errors use the
  auth API error shape (400 / 401 / 413).
- `auth_api.rs` — signup/login/me with basicproject_go's response shapes: `TokenResponse {token, tokenType,
  expiresInMs, user}`, `UserResponse {id,email,name,level,createddate}` (same keys as the generated User JSON), errors
  `{status,message,fieldErrors,timestamp}` with real HTTP status codes (signup 201/400/409, login 200/401, me 200/401;
  unlike generated CRUD, which is HTTP 200 + `code`).
- `support/auth.rs` — unified JWT (HS256, claims `{sub, id, email, level?, iat, exp}`); `make_token` issues,
  `session_from_parts` feeds the `Option<Session>` extractor used by generated handlers.
- `support/password.rs` — bcrypt `$2a$` cost 10 (compatible with Go hashes); `generate_passwd_blocking` in handlers.

## Adding a table

1. Add `CREATE TABLE {name}_tb` with `{prefix}_` columns to `db/schema.sql` and apply it to the dev DB.
2. Optionally add `{ "name": ..., "session": [...], "protect": [...], "join": [...], "read": "owner|login|public" }`
   to `model.json`. Standard tables: user (`protect: ["level"]`, reads are self-or-admin), board (author `session`,
   `join` user, `read: "login"`).
3. `make gen`, then `make check`. No changes to `main.rs` are needed.
